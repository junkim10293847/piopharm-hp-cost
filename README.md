# 화성·평택 매출원가

ERP에서 내려받은 **기초 자료(엑셀)** 를 넣으면 — 시트별 파일을 하나씩 넣어도 되고, 한 파일로 모아 넣어도 됩니다

1. 당월 출하 매출을 **화성 / 평택**으로 나누고
2. 평택은 **로트별**, 화성은 **품목별** 재료원가(원료·자재)를 계산해
3. **엑셀 보고서**(요약 · 평택_로트별 · 화성_품목별 · 확인사항)로 내보냅니다.

웹 화면과 명령줄 도구가 같은 계산 엔진(`src/engine.js`)을 쓰므로 어느 쪽으로 돌려도 결과가 같습니다.

---

## 쓰는 방법

### 1) 웹에서 (설치 없음)
GitHub Pages 주소를 열면 자료별 칸 8개가 있습니다. 칸마다 **파일 선택**(또는 끌어다 놓기)으로 ERP 파일을 넣습니다.

| 칸 | 자료 | |
|---|---|---|
| 1 | 평택 로트목록 (제품코드·로트번호·완료수량·생산공장·포장공장) | 필수 |
| 2 | 출하대장 (당월) | 필수 |
| 3 | 발주 현황 | 필수 |
| 4 | 작업지시현황 (지시번호 10-30 = 평택) | 필수 |
| 5 | 제품 단가 대장 (당월) | 필수 |
| 6 | 제품 단가 대장 (전월) | 선택 — 전월 생산분이 이번 달 출하될 때 |
| 7 | 제품 단가 대장 (전전월) | 선택 — 더 오래된 생산분 |
| 8 | FCO 수불 | 선택 — 평택 미출고 기말 제품재고액 |

- 파일 이름은 상관없습니다. 넣은 칸의 용도로 씁니다. 시트가 여러 개면 칸 안에서 고르면 됩니다.
- 필수 5칸이 차면 바로 계산되고 **엑셀 다운로드**로 결과를 받습니다.
- **검수** 탭: 로트·전월 생산 출하·미출고 재고를 하나씩 넘기며(◀ ▶, 키보드 ← →) 로트목록·출하대장·단가대장·발주·작업지시·FCO 매칭과 계산식을 봅니다. 「확인」 표시는 이 브라우저에 월별로 남습니다.
- **월별 자료 보관함**: 「미가공 파일 넣기」로 지난 달 파일들을 한꺼번에 넣으면 월별로 저장됩니다. 칸으로 계산할 때도 보관함의 이전 달 단가대장·로트목록을 자동으로 씁니다. 다른 PC에서는 「백업 파일 받기」 → 「백업 불러오기」.
- **계산 규칙**: 평택비율·평택 판단·원료 코드 등 바뀔 수 있는 기준을 화면에서 고치면 바로 다시 계산합니다. 「기본값으로」로 되돌립니다.
- **보관함 고치기**: 보관함 표의 ✓ 칸을 누르면 그 자료를 다른 월로 옮기거나 지우고, 로트목록은 행마다 고칠 수 있습니다(수정 이력이 남음).
- **미출고 재고** 탭: FCO 현재고가 남은 제품만, 평택/화성·기타/전체로 거릅니다. 「재고 저장」으로 월별 평택 재고를 이 브라우저에 남깁니다.
파일은 브라우저 안에서만 읽고 계산하며 서버로 보내지 않습니다.
로컬에서는 `index.html`을 브라우저로 열어도 됩니다.

### 2) 명령줄 / 자동 실행
```bash
npm install
node cli/hp-cost.js "2026-09 기초파일.xlsx"            # 같은 폴더에 결과 저장
node cli/hp-cost.js data/inbox                        # 폴더 안 파일 처리 → data/inbox/output/
node cli/hp-cost.js 발주.xlsx 출하.xlsx 단가9월.xlsx …  # 시트별 개별 파일을 묶어서 계산
node cli/hp-cost.js 기초파일.xlsx --month 9 --fx 1360  # 당월·환율 직접 지정
node cli/hp-cost.js 기초파일.xlsx --ratio ratio.json   # 생산구분별 평택비율 변경
node cli/hp-cost.js data/inbox --json                 # 결과 요약을 JSON으로 (다른 시스템 연동용)
```
Windows에서는 `data\inbox`에 파일을 넣고 **`월마감_실행.bat`** 을 더블클릭하면 됩니다.
작업 스케줄러에 이 배치 파일을 등록하면 매달 정해진 날 자동으로 돌아갑니다.

## 기초 파일 형식

자료 6가지가 있으면 됩니다. **한 파일의 여러 시트**로 넣어도, **자료마다 따로 받은 파일**로 넣어도 됩니다.
종류는 ① 시트 이름 → ② 머리글 → ③ (시트가 하나뿐인 파일이면) 파일 이름 순서로 알아봅니다.
그래서 ERP에서 받은 파일의 시트 이름이 `Sheet1`이어도 그대로 넣으면 됩니다.
출하대장·제품 단가 대장은 시트나 파일 이름에 `9월`처럼 월이 있으면 그 달 자료로 봅니다.
같은 종류가 두 번 들어오면 먼저 넣은 것을 쓰고 화면에 표시합니다(단가 대장은 월이 다르면 모두 사용).
폴더로 돌리면, 혼자 다 갖춘 파일은 따로 계산하고 나머지 개별 파일들은 한 묶음으로 계산합니다.

| 필요한 자료 | 이름에 들어갈 단어 | 쓰는 열(머리글) |
|---|---|---|
| 발주 현황 | `발주 현황` | 매출 월, LOT, 제품코드, 구분, 수주수량, 수주단가 |
| 작업지시현황 | `작업지시` | 제품로트번호, 지시제품, 규격 |
| 출하대장 | `출하대장` (예: `9월 출하대장`) | 로트번호, 품목코드, 제품명, 매출업체, 출하량, 중량, 공급가액 |
| 제품 단가 대장 | `단가 대장` (예: `9월 제품 단가 대장`, 월별 여러 장 가능) | 품목코드, 생산중량, 자재코드, 상세금액 |
| 자재투입현황 | `자재투입` | 투입번호, 제조일자, 생산중량, 투입중량, 반제품/자재로트번호 |
| 평택 로트목록 | 기존 `당월 생산` 시트(제공자료 칸) | 제품코드, 로트번호, 제품명, 고객사, 평택비율(생산구분), 규격, 완료수량, 완료단가 |

- 열은 **위치가 아니라 머리글 이름**으로 찾습니다. 띄어쓰기·줄바꿈은 무시합니다.
- 로트목록의 `전월 생산` 구간은 전월 로트로 처리합니다.
- 외화 수주는 단가 수식의 `*1360`, 부분 출하 보정계수는 생산중량 수식의 `*AX63`에서 자동으로 읽습니다.
  로트목록을 표로 따로 관리한다면 `환율적용`(Y) · `보정계수` 열을 두면 됩니다.

계산 기준은 [docs/계산기준.md](docs/계산기준.md)에 있습니다.

## 구조
```
src/engine.js     계산 엔진 (시트 읽기 → 로트·품목 계산)  ← 업그레이드는 주로 여기
src/parse.js      SheetJS 통합문서 → 엔진 입력 변환
src/report.js     결과 집계 · 엑셀 보고서 생성
index.html        웹 화면 (GitHub Pages로 배포)
cli/hp-cost.js    명령줄 도구 (파일·폴더 일괄 처리, JSON 출력)
fixtures/         테스트용 가상 기초 파일 생성기 (실제 회사 데이터 없음)
test/             계산 검증 테스트 (npm test)
.github/workflows 푸시할 때마다 테스트, main 브랜치는 웹 자동 배포
```

## 데이터 보안
- `.gitignore`가 모든 엑셀 파일과 `data/` 폴더를 막아 **회사 자료가 저장소에 올라가지 않습니다.**
- 테스트는 `fixtures/sample.js`가 만드는 가상 데이터만 씁니다.

## 검증 이력
| 기준월 | 확인 내용 |
|---|---|
| 2026-09 | 당월 47개 로트가 기존 수식 시트와 행 단위로 일치. 총 6,138,643,401원 = 평택 1,528,496,411원 + 화성 4,610,146,990원. 화성 방식(출하중량 × kg당 원가)을 평택 24개 품목에 적용한 값이 로트 방식과 0.02% 이내 |
